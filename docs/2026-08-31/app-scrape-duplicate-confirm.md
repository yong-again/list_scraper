# 중복/재요청 스크랩 확인 창 추가 (2026-08-31)

## 문제 상황

사용자 피드백: "스크랩 시작을 다시 누르니까 재시작이 되고, 계속 요청하는 것같음. 같은 팩션이
진행중이고 요청이 들어오면 다시 시작하겠습니까? 라고 물어서 무한 요청을 사전에 차단해야 할듯.
그리고 이미 스크래핑이 완료된 팩션도 진행할 때 이미 내역이 존재합니다. 다시 가져오시겠습니까?
류의 메시지를 띄워서 진행하는게 좋을듯"

## 원인 분석

Streamlit은 세션당 단일 스레드로 동작해서 스크랩 루프가 도는 동안은 그 스크립트 실행이
끝나기 전까지 다른 상호작용을 처리하지 못한다 (즉 진짜 "동시 진행"은 이 구조상 발생할 수
없음). 하지만 스크랩이 수십 초~수 분 걸리는 동안 화면이 정지된 것처럼 보여서, 사용자가
"스크랩 시작"을 여러 번 눌러버리면 그 클릭들이 큐에 쌓였다가 이전 실행이 끝난 직후 연달아
처리되면서 **같은 팩션을 다시 스크랩하는 게 반복되는 것처럼 보임**. 여기에 더해, 이미
`army_list/`에 xlsx가 있는 팩션(✅ 표시된 팩션)을 다시 선택해 스크랩해도 아무 확인 없이 바로
재수집이 시작되는 것도 원인.

## 수정 내용 (`app.py`)

"스크랩 시작" 클릭 시 곧바로 실행하지 않고, 아래 두 조건 중 하나라도 해당하면 먼저 확인
창을 띄우도록 바꿨다 (둘 다 해당하면 메시지가 합쳐져서 한 번에 표시됨):

1. **중복 요청**: 방금(60초 이내) 완료한 스크랩 요청과 선택한 팩션 조합이 완전히 같으면
   → "방금 같은 팩션으로 스크랩을 요청했습니다. 다시 가져오시겠습니까?"
   (`st.session_state["last_scrape_request"]`에 마지막 요청의 팩션 목록 + 완료 시각을 기록해
   비교. 세션별로 관리되므로 다른 사람/탭에는 영향 없음)
2. **이미 수집됨**: 선택한 팩션 중 `army_list/`에 이미 xlsx가 있는 게 있으면
   → "이미 수집된 팩션이 있습니다: {팩션명, ...}. 다시 가져오시겠습니까?"

확인 창은 "다시 가져오기"(실제 재스크랩 진행) / "취소"(아무 것도 하지 않고 닫힘) 두 버튼으로
구성. 처음 수집하는 팩션이고 최근 중복 요청도 아니면 기존처럼 확인 없이 바로 진행되어, 평소
사용 흐름에는 추가 클릭이 생기지 않는다.

실제 스크랩 실행 로직은 `run_scrape_job()` 함수로 분리해서, "바로 진행" 경로와 "확인 후 진행"
경로가 동일한 코드를 공유하도록 정리했다 (진행 상황 표시, 완료/실패 처리, 캐시 무효화, 자동
팩션 선택 등 기존 동작은 그대로 유지).

## 검증

셸(device_bash)이 계속 응답하지 않아 사용자 컴퓨터에서 직접 확인은 못 함. 클라우드
컨테이너에 스트림릿을 띄우고 `pipeline.run_faction`을 빠른 스텁으로 교체해 Playwright로
아래 시나리오를 모두 확인:

- 한 번도 수집한 적 없는 팩션을 선택 → 확인 없이 바로 "🔄 스크래핑 진행 중..." 표시
- 방금 스크랩을 마친 팩션을 다시 선택 후 "스크랩 시작" → "방금 같은 팩션으로 스크랩을
  요청했습니다. 이미 수집된 팩션이 있습니다: ... 다시 가져오시겠습니까?" 확인 창 표시
  (두 조건이 겹쳐 메시지가 합쳐지는 것도 확인)
- 확인 창에서 "취소" 클릭 → 재스크랩 없이 창만 닫힘 (데이터 갱신 시각이 그대로임을 확인)
- 확인 창에서 "다시 가져오기" 클릭 → 실제로 재스크랩이 진행되어 완료됨
- 새 세션에서 아예 새로운 팩션을 선택 → 확인 없이 바로 진행 (기존 사용 흐름 유지 확인)
